# 工作方式约定

> 这份文档是给 AI 助手看的，约定我们怎么配合推进项目。

## 我的基本情况

- **身份**：全栈程序员，前后端部署运维都会
- **英语水平**：一般，有 AI 辅助没问题
- **时间投入**：每天 1 小时 + 周末每天 4 小时 = 13 小时/周
- **目标**：赚钱（被动收入），第一个产品目标 $500-$1K MRR
- **心态**：热情高，但担心 burnout，所以要控制节奏

## 配合原则

### 1. 按周计划，不按天
- 只规定"这周要完成什么"，不规定"哪天做什么"
- 节奏自己把握，有事耽误了也没关系，周末补上
- 避免"今天没完成计划就有挫败感"的情况

### 2. 先验证，再开发
- Landing Page 先上，验证有人感兴趣再写代码
- 第一笔钱比什么都重要
- 不要闷头开发一个月，结果发现没人要

### 3. MVP 要极简
- 能砍的功能全砍掉
- 够用就好，不要追求完美
- 多出来的功能等用户提了再加

### 4. 自动同步到 GitHub
- 你帮我改的文件，自动帮我 git add/commit/push
- 我自己改的，说一声"帮我 push 一下"就行
- commit message 写清楚改了什么

### 5. README 是"云端记忆"
- 每周结束时更新 README 的进度清单
- 重要的决策和结论都记录到 docs/ 里
- 换设备、换会话，看 README 和 docs 就能接上

### 6. 坦诚直接
- 有风险直接说，不要只说好听的
- 方向不对该止损就止损
- 不懂的地方直接问，不用猜

## 我希望你帮我做的事

1. **拆解任务** — 把大目标拆成具体可执行的小步骤
2. **写代码** — 前后端代码、配置文件
3. **写文档** — 产品文档、技术文档、营销文案
4. **出主意** — 遇到问题给建议，分析利弊
5. **帮我推进** — 提醒我下一步做什么，别跑偏
6. **同步进度** — 更新 README，推送到 GitHub

## 我不希望的事

- 不要太啰嗦，直接说重点
- 不要把简单的事情复杂化
- 不要每次都从头讲一遍（从 docs 里读上下文）
- 不要过度优化，够用就好

## 新会话快速上手

如果是新的 AI 对话，按以下顺序读文档：

1. **README.md** — 项目概览 + 当前进度 + 下一步
2. **docs/01-项目背景与定位.md** — 做什么、为什么做
3. **docs/02-执行计划总览.md** — 整体计划、当前阶段
4. **docs/03-竞品分析.md** — 市场情况
5. **docs/04-技术栈.md** — 技术选型
6. **docs/05-工作方式约定.md** — 怎么配合（就是这份文档）

读完这些，就能完全了解项目情况，直接开始干活。
