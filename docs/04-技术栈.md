# 技术栈

## 选型原则

- **怎么简单怎么来** — 个人项目，不要折腾基础设施
- **免运维优先** — 能托管的就不自建
- **生态成熟** — 出了问题 Google 一下就能找到答案
- **免费额度够用** — 起步阶段尽量不花钱

## 技术选型

| 层 | 技术 | 选型理由 |
|----|------|----------|
| **前端框架** | Next.js (App Router) | React 生态最成熟的全栈框架，Vercel 一键部署 |
| **样式** | Tailwind CSS | 写样式快，不用想类名，个人开发效率高 |
| **后端** | Next.js API Routes | 不用单独搞后端服务，跟前端同一个项目 |
| **数据库** | Supabase (PostgreSQL) | 免运维，带 Auth，有免费额度，Postgres 功能强 |
| **部署** | Vercel | Next.js 亲爹，一键部署，免费额度够用 |
| **支付** | Lemon Squeezy | 个人身份可用，MoR 模式（代缴全球税费），不需要海外公司和银行卡 |
| **邮件** | Resend | 简单好用，API 友好，免费额度够起步 |
| **域名** | .com 或 .io | Namecheap 或 GoDaddy 购买 |
| **代码托管** | GitHub | 私有仓库，免费 |

## 为什么不用其他方案

### 为什么不用自建后端？（Express/Fastify 等）
- 需要自己搞服务器、运维、监控、部署
- 个人项目，能省则省
- Next.js API Routes 完全够用

### 为什么不用 Firebase？
- Supabase 是 PostgreSQL，更灵活，数据迁移更方便
- Firebase 的 NoSQL 后期复杂查询很痛苦
- Supabase 有 Row Level Security，同样支持 Auth

### 为什么不用 Stripe？
- Stripe 需要海外公司和银行账户
- Lemon Squeezy 个人身份就能用，是 MoR（Merchant of Record）模式
- 等月收入 $3K+ 了再考虑切换到 Stripe

### 为什么不用 AWS/GCP？
- 太复杂，个人项目没必要
- 账单不可控，容易超支
- Vercel + Supabase 免费额度够起步

## 成本估算（起步阶段）

| 服务 | 费用 | 说明 |
|------|------|------|
| 域名 | $10-15/年 | 每年付一次 |
| Vercel | $0 | Hobby 计划免费，够起步 |
| Supabase | $0 | Free plan 够起步，Pro $25/月（用户多了再升） |
| Lemon Squeezy | 5% + $0.50/笔 | 有收入才扣费 |
| Resend | $0 | 每天 100 封免费 |

**起步阶段总成本：约 $10/年（只有域名钱）**

等有收入了，再根据用户量考虑升级 Supabase Pro（$25/月）。

```
│   ├── dashboard/            # 用户后台
│   │   ├── page.tsx          # 项目列表
│   │   └── [projectId]/      # 单个项目详情
│   │       └── page.tsx      # 错误列表
│   └── api/                  # API 路由

└── ...
```
