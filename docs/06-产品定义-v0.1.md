# 产品定义 v0.1

> 第 1 周产出，状态：待 review。所有带「决策」的段落都需要你拍板。

## 0. 一句话

**给独立开发者的错误收件箱：$5/月固定价，不再为事件额度焦虑。**

## 1. 先纠正一个定位问题

原来的一句话是「便宜 80% 的 Sentry」。调研后发现这个说法打不中人：

- Sentry 免费版（Developer）是 **1 个用户、5,000 errors/月、30 天保留、无限项目、邮件告警**，$0。
- 目标用户是「有副业项目的独立开发者」，他们**本来就付 $0**，不是 $26 的 Team 用户。
- 所以「比 $26 便宜 80%」是在跟一个他们没买的套餐比价。

真正让人愿意掏钱的触发点，按证据排序：

| 排序 | 痛点 | 证据 |
|---|---|---|
| 1 | 事件额度焦虑：bug 爆发时额度烧光，最需要看错误的时候被限流/丢事件 | HN 2026-07 评论：第 10 万个事件和第 1 个事件价值一样，但账单差几百刀；HN 2025-11：公司自建 Sentry 一直丢事件，没人有空修 |
| 2 | Sentry 越来越重、太复杂，80% 功能用不上 | HN 2025-06：「I love Sentry but it has become a bit over-the-top complicated」 |
| 3 | 多个副业项目来回切换后台很烦 | 项目文档 03 里已有真实用户原话，愿为聚合 dashboard 付 $10/月 |
| 4 | 自建免费方案要运维，出事没人管 | GlitchTip 用户原话：磁盘满了才发现，一周错误全丢 |

**结论：卖「固定价 + 额度不焦虑 + 一个收件箱管所有项目 + 3 分钟接入」，不要卖「便宜」。**
便宜只是结果，不是卖点。价格敏感的人会直接去用免费版或自建。

## 2. 用户画像

### A. 多项目独立开发者（主目标）

- 手上 2-5 个副业项目，都接了 Sentry 免费版（或只接了最赚钱的那个）
- 平时没时间运维，出问题靠用户反馈
- 经历过至少一次「bug 刷屏把额度烧完」或「不知道哪个项目在报错」
- 付费意愿：$5/月可以无脑付，$15 会犹豫

### B. 2-3 人小团队（次目标，MVP 先不专门服务）

- 用 Sentry Team $26/月，只为 2-3 个账号
- 不需要 SAML、不需要 APM，只需要「一起看同一个错误列表」
- 注意：Sentry 免费版限 1 用户，所以小团队是被迫付费的，这是真实付费场景

> 决策 D1：主目标是 A 还是 A+B。选 A+B 就要在 MVP 里做多用户（增加约 3-5h 开发量）。**建议先 A，B 留到第 7 周发布后再做。**

## 3. MVP 范围（砍到不能再砍）

### 必做

1. **浏览器 JS SDK**：一行 `<script>` 接入，捕获 `window.onerror` / `unhandledrejection`，带 stack、URL、UA、项目 DSN
2. **接收 & 分组**：按 fingerprint（错误类型 + 归一化 message + 顶层栈帧）分组，同一错误只算一个 issue
3. **Dashboard**：项目列表 → issue 列表（次数/首次/最近）→ issue 详情（stack、浏览器、URL、事件时间线）；resolve / ignore
4. **邮件告警**：新 issue、回归 issue 发邮件；同一 issue 24h 内只发一封（防告警疲劳）
5. **账号 + 支付**：邮箱注册登录 + Lemon Squeezy 订阅

### 明确不做

- Source map、Breadcrumbs、Session Replay、APM/Tracing
- Node/Python/Go 等非浏览器 SDK
- Slack / Discord / Telegram 集成
- 团队角色、权限、审计日志
- 自定义告警规则（MVP 只有「新错误」和「回归」两种）

> 决策 D4：SDK 路线。
> **方案 A（推荐）**：自己写约 100 行的极简 JS SDK，可控、够快，4 周内稳。
> **方案 B**：兼容 Sentry SDK 的 envelope 上报协议，用户改一行 DSN 就能迁移（Bugsink / GlitchTip / Telebugs 都这么做），迁移摩擦最低，但要解析 Sentry 协议，至少多 1 周，且容易踩格式坑。
> 建议 MVP 走 A，第 5-6 周如果还有时间再加 B 作为「drop-in 迁移」。

## 4. 关键工程设计：让「固定价」不亏钱

$5/月不限事件的前提是**不能真把每条事件都存下来**。

- 每个 issue 最多保留 50 条样本事件，其余只累加计数（Sentry 自己也是这么做的）
- 按 issue 去重后，事件量对存储成本的影响大幅下降
- 每个项目做入口限流（例如 1,000 events/min），超出的丢弃但**继续计数**，dashboard 显示「已折叠 N 条同类事件」
- 90 天保留期，过期聚合清理

成本估算（100K events/月、约 500 个 issue、每条约 1.5KB）：

- 实际存储约 75MB/月（50 条样本/issue）
- 90 天约 225MB → Supabase 免费 500MB 可撑 2 个重度用户；升级 Pro $25/月后可撑 15-20 个
- **盈亏平衡点约 5 个付费用户**（$25 成本 vs $5×5）

> 决策 D3：怎么对外表达「不限事件」。
> **建议表述**：`No event quotas. Bug storms cost you nothing.` + FAQ 里解释「我们会自动合并/采样，不会给你寄账单」。
> 不要写「unlimited events」这种绝对词，避免被较真用户抓住限流打脸。
> 如果你坚持字面 unlimited，就必须接受极端情况下亏钱或偷偷限流，两者都会伤信任。

## 5. 定价 v0.1

| | Free | Solo（唯一付费档） |
|---|---|---|
| 价格 | $0 | **$5/月**（年付 $50） |
| 项目数 | 1 | 不限 |
| 事件 | 5,000/月 | 不限额度，自动合并/采样 |
| 保留期 | 7 天 | 90 天 |
| 用户数 | 1 | 1 |
| 邮件告警 | 有 | 有 |
| 历史趋势 | 无 | 有 |

免费版的设计逻辑：**能完整体验核心价值（收到错误 + 邮件告警），但不够正经跑多个项目。**

- 免费 1 个项目：让他能接自己最在意的那一个项目
- 7 天保留：真实用起来会觉得短，是升级动机
- 不做「每天 100 条错误」的旧方案：太小气，连试用都跑不通

> 决策 D2：免费版额度是否照上表。备选：免费 2 个项目 / 5,000 事件 / 30 天保留（更接近 Sentry 免费版，转化会更难）。
> **建议按上表**，故意留一个「保留期只有 7 天」的缺口作为升级理由。
>
> 决策 D5：是否加第二档。**建议 MVP 只有 $5 一档**，少一个价格选项就少一半解释成本；第 7 周有人抱怨「想加队友」再加 $12/月 Team。

## 6. 竞争格局（更新 docs/03 缺失的部分）

| 产品 | 免费额度 | 最低付费档 | 形态 |
|---|---|---|---|
| Sentry | 5K errors/月，1 用户，30 天 | $26/月（50K，无限用户） | SaaS |
| GlitchTip | 1K events/月 | $15/月（100K） | SaaS + 可自建 |
| Bugsink | 15K events/月（保留 5K，1 用户） | €16/月（75K，无限用户） | SaaS + 可自建（自建免费不限量） |
| Telebugs | 无 | $99/月托管；$299 一次性自建 + $99/年更新 | 自建/托管 |
| **我们** | 5K/月，1 项目，7 天 | **$5/月** | SaaS |

结论：

1. **$5 确实是全市场最低的托管付费档**（比 GlitchTip $15、Bugsink €16 低 3 倍），有真实空位。
2. 但最近一年冒出来 3 个「Sentry 替代」项目（Bugsink、Telebugs、GlitchTip），说明这是**正在变拥挤的赛道**，不是蓝海。
3. 最大的替代威胁不是竞品，而是「Sentry 免费版 + 自建免费方案」——我们必须在「省心」和「多项目」上赢，不能在功能上比。

## 7. 风险与止损

| 风险 | 影响 | 应对 |
|---|---|---|
| Sentry 免费版对单人项目够用 | 转化率低 | 只打「已经烧过额度 / 有 3+ 项目」的人，不打泛开发者 |
| 免费/自建竞品多 | 价格战 | 不比功能，比「不用运维 + 3 分钟接入」 |
| $5 ARPU 太低 | 100 用户才 $500 MRR | 获客必须接近零成本（内容 + 社区），不投广告 |
| 固定价被极端流量打穿 | 亏钱 | issue 分组 + 样本上限 + 项目级限流 |
| 4 周 MVP 遇上正职 | 延期 | 严格按第 3 节范围，任何新功能进 backlog 不进 MVP |

**止损线（写死，到点就执行）**

- 第 1 周：找不到 3 个说「愿意付 $5」的真人 → 不开发，调整方向
- 第 2 周：Landing Page 发出后 2 周内 < 50 邮箱且 < 10 人愿意付费 → 不进入第 3 周开发
- 第 6 周：没有 1 个真实付费用户 → 停止投入，复盘后换方向
